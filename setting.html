ฟีเจอร์ของระบบ

ออกแบบมาเพื่อให้การตรวจจุดมีหลักฐาน ตรวจย้อนหลังได้ และลดการบันทึกจากระยะไกล

สแกนผ่านกล้องมือถือด้วย HTML5 และถ่ายภาพแนบเมื่อพบเหตุการณ์

03 / INSTALLATION

ติดตั้งระบบทีละขั้นตอน

ทำตามลำดับจากฐานข้อมูล → การเชื่อมต่อ → พิกัดจุดตรวจ → ป้าย QR → เว็บไซต์ Production

01

ติดตั้ง Backend บน Google Sheets

  1. สร้างสเปรดชีต: เปิด Google Sheets ↗ แล้วสร้างชีตเปล่า ตั้งชื่อ เช่น DB_Security_Patrol
  2. เปิด Apps Script: เลือก ส่วนขยาย (Extensions) → Apps Script และตั้งชื่อโปรเจกต์ เช่น Patrol_API
  3. วางโค้ด: ลบโค้ดเริ่มต้นใน Code.gs แล้ววางเนื้อหาจากไฟล์ Code.gs ของโปรเจกต์จริง จากนั้นบันทึก
  4. สร้างชีตเริ่มต้น: เลือกฟังก์ชัน setupDatabase แล้วกด Run อนุญาตสิทธิ์ตามหน้าจอ (ตรวจสอบชื่อแอปและสิทธิ์ก่อนยืนยัน)

เมื่อฟังก์ชันทำงานเสร็จ ควรมี 4 ชีต: Checkpoints (จุดตรวจและพิกัด), Guards (เจ้าหน้าที่), Reports (รายงานและ DistanceMeters) และ Settings (การตั้งค่า)

ตั้งรหัสผ่านผู้ดูแลระบบ

เรียก showAdminPassword แล้วดูรหัสชั่วคราวใน Execution log หรือแก้ค่า newPassword ในฟังก์ชัน setAdminPassword แล้วเรียกใช้หนึ่งครั้ง อย่าเปิดเผยรหัสผ่านหรือภาพ Execution log ต่อผู้อื่น

Deploy Apps Script เป็น Web App

  1. เลือก Deploy → New deployment → Web app
  2. ตั้ง Description เป็น Production v1, Execute as เป็น Me และ Who has access เป็น Anyone ตามรูปแบบของคู่มือต้นฉบับ
  3. กด Deploy แล้วคัดลอก Web app URL ที่ลงท้ายด้วย /exec
สำคัญ: ตรวจสอบสิทธิ์ก่อนเปิดให้ Anyone

การเปิด Web App ให้ Anyone เข้าถึงได้ทำให้ endpoint เป็นสาธารณะ ต้องตรวจสอบว่าโค้ด Backend ตรวจสิทธิ์ของทุกคำสั่งที่แก้ไขหรืออ่านข้อมูลอ่อนไหวจริง และไม่พึ่งการซ่อนปุ่มในหน้าเว็บอย่างเดียว

02

เชื่อมต่อ Frontend กับ Web App API

เปิด config.js ของโปรเจกต์จริง นำ URL จากขั้นตอน Deploy มาใส่ในตัวแปร API_URL แล้วบันทึกไฟล์

config.js · ตัวอย่าง
// Configuration for QR Patrol Check-in
const API_URL = 'https://script.google.com/macros/s/ใส่_WEB_APP_ID_ของคุณที่นี่/exec';

แทนที่ URL ตัวอย่างด้วย URL จริงของ deployment; อย่านำ URL ที่มีข้อความตัวอย่างไปใช้งานจริง

03

กำหนดพิกัดจุดตรวจและรัศมี 50 เมตร

ระบบใช้ระยะจากพิกัดจุดตรวจถึงตำแหน่งของเจ้าหน้าที่ ค่าเริ่มต้นของ Radius คือ 50 เมตร โดยตั้งจุดตรวจได้ 3 วิธี

วิธีที่ 1 · ปักหมุด ณ จุดตรวจจริง

  1. แอดมินไปที่จุดตรวจพร้อมมือถือหรือแท็บเล็ต
  2. เปิดหน้าเว็บและเลือกจุดตรวจนั้น
  3. กด “ปักหมุดพิกัดนี้เป็นจุดตรวจ (50 เมตร)”

วิธีที่ 2 · ผ่านแดชบอร์ดแอดมิน

  1. เข้าสู่หน้า ผู้ดูแลระบบ → จัดการจุดตรวจ → แก้ไข
  2. กด “ดึงพิกัดที่ฉันยืนอยู่” หรือกรอก Latitude, Longitude, Radius
  3. กด บันทึกจุดตรวจ

วิธีที่ 3 · แก้ไขใน Google Sheets

เปิดชีต Checkpoints แล้วกรอกคอลัมน์ Latitude, Longitude และ Radius (เช่น 50)

จุดตรวจที่ยังไม่ปักหมุด

ตามคู่มือต้นฉบับ จุดตรวจที่ไม่มีพิกัดจะอนุญาตให้สแกนได้ตามปกติ จึงยังไม่อยู่ภายใต้การบังคับใช้ geofence; ปักหมุดทุกจุดก่อนเปิดใช้งานจริง

04

สร้างและพิมพ์ป้าย QR Code

  1. เปิด print-checkpoints.html ของโปรเจกต์ หรือหน้าดังกล่าวบนโดเมนที่ Deploy แล้ว
  2. คัดลอกข้อมูลจากชีต Checkpoints แล้ววางลงในช่องนำเข้า
  3. ตรวจสอบป้าย QR และ Badge รัศมี 50 เมตร
  4. กด “พิมพ์ป้าย QR Code (A4)” แล้วนำป้ายไปเคลือบและติด ณ จุดตรวจจริง

คอลัมน์ที่รองรับ: CheckpointID, PostID, CheckpointName, Zone, QRToken, Active, Latitude, Longitude, Radius

05

Deploy หน้าเว็บขึ้น Vercel

เบราว์เซอร์มือถือโดยทั่วไปต้องการบริบทที่ปลอดภัย (HTTPS) เพื่อใช้กล้องและ Geolocation บนโดเมนจริง สามารถ Deploy ด้วย Vercel CLI จากโฟลเดอร์โปรเจกต์:

TERMINAL · ในโฟลเดอร์โปรเจกต์
npm i -g vercel
vercel --prod --yes

หรือ Push โปรเจกต์ขึ้น GitHub แล้วเชื่อม repository ผ่าน Vercel Dashboard ↗ ตรวจสอบ API_URL ให้ถูกต้องก่อนเผยแพร่

04 / FIELD GUIDE

คู่มือการใช้งาน

สำหรับเจ้าหน้าที่ รปภ.

  1. เปิดลิงก์เว็บบนมือถือผ่าน Chrome หรือ Safari
  2. อนุญาต Camera และ Location เมื่อเบราว์เซอร์ร้องขอ
  3. ตรวจแถบสถานะ GPS ให้พร้อมใช้งาน และเลือกชื่อของตนเอง
  4. กด “เปิดกล้องสแกน QR” แล้วส่องป้าย ณ จุดตรวจ
  5. หากอยู่ในรัศมี ระบบแสดงระยะห่าง; หากอยู่นอกรัศมี ระบบแจ้งเตือนและไม่ให้ส่งผล
  6. เลือกผล ปกติ / ผิดปกติ แนบภาพถ้ามี แล้วกด “บันทึกผลการตรวจ”

สำหรับผู้ดูแลระบบ

  1. กด “ผู้ดูแลระบบ” ที่หน้าเว็บ แล้วใส่รหัสผ่านแอดมิน
  2. Reports: ดูประวัติ ภาพหลักฐาน ระยะห่างจริง และลิงก์พิกัดบน Google Maps
  3. Checkpoints: เพิ่ม/แก้ไข เปิด-ปิดจุดตรวจ ปักหมุด GPS และสร้าง QR Token ใหม่
  4. Guards: เพิ่มหรือแก้ไขรายชื่อเจ้าหน้าที่
สถานะการตรวจระยะ

ภายในรัศมี: แสดงข้อความสีเขียวพร้อมระยะห่าง · นอกพื้นที่: แสดงข้อความเตือนและไม่อนุญาตให้ส่งผล ตามพฤติกรรมที่อธิบายในคู่มือต้นฉบับ

05 / TROUBLESHOOTING

ปัญหาที่พบบ่อย

เปิดกล้องไม่ได้

ตรวจสอบว่าเว็บเปิดผ่าน HTTPS และได้อนุญาตสิทธิ์ Camera ในเบราว์เซอร์แล้ว หากเคยปฏิเสธ ให้แก้สิทธิ์เว็บไซต์ในการตั้งค่าเบราว์เซอร์

GPS แจ้งว่าอยู่นอกพื้นที่ ทั้งที่ยืนอยู่จริง

พิกัดจุดตรวจอาจคลาดเคลื่อน หรือ GPS ในอาคารรับสัญญาณไม่ดี ให้ตรวจความแม่นยำของตำแหน่ง ปักหมุดใหม่ ณ จุดจริง หรือปรับ Radius หลังประเมินความเสี่ยงและบันทึกเหตุผล

กดบันทึกแล้ว Error หรือข้อมูลไม่ลงชีต

ตรวจสอบ URL ใน config.js ให้ตรงกับ Web App URL ที่ลงท้าย /exec และตรวจสิทธิ์ของ Apps Script deployment หากแก้ Backend แล้วอาจต้อง Deploy เวอร์ชันใหม่

ลืมรหัสผ่านแอดมิน

ผู้ดูแลโปรเจกต์ Apps Script สามารถเรียก showAdminPassword แล้วดู Execution log ตามคู่มือต้นฉบับ ควรจำกัดผู้ที่เข้าถึงโปรเจกต์และไม่ส่งต่อ log

06 / OPERATIONAL NOTES

ข้อควรคำนึงก่อนใช้งานจริง

  • GPS ไม่ใช่หลักฐานที่ปลอมแปลงไม่ได้: ตำแหน่งจากอุปกรณ์อาจคลาดเคลื่อนหรือถูกปลอมได้ ควรใช้ร่วมกับการตรวจสอบอื่นและการสุ่มตรวจหน้างาน
  • ตรวจที่ Backend: การบล็อกในหน้าเว็บอย่างเดียวไม่เพียงพอ หากต้องการบังคับใช้ระยะจริง Backend ต้องตรวจคำขอและกฎธุรกิจด้วย
  • สิทธิ์และข้อมูลส่วนบุคคล: จำกัดสิทธิ์เข้าถึงชีต/ภาพหลักฐาน กำหนดอายุเก็บข้อมูล และแจ้งเจ้าหน้าที่เรื่องการใช้ข้อมูลตำแหน่ง
  • จุดที่ไม่มีพิกัด: ตั้งพิกัดครบทุกจุดก่อนเริ่มใช้กฎ 50 เมตร เพราะคู่มือต้นฉบับระบุว่าจุดที่ยังไม่ตั้งพิกัดสแกนผ่านได้
